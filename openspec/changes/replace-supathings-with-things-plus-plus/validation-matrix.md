## Blockers

- Any mismatch in the 37/17/25 closure, exact 70-tool union, explicit allowlists, group topology, root-plugin singularity, or active SupaThings absence blocks cutover.
- Any Things MCP logic outside the one `things` group or any local/remote path other than exact `/mcp/things` blocks cutover. Coverage may expand only by explicit revision and never contract below 70/37/17/25/16.
- Any package hash/version mismatch, raw/arbitrary execution path, annotation/scope mismatch, secret/content leak, or failed write-verification contract blocks the affected server.
- Any downstream tarball/lock/source/patch/build/materialization mismatch, non-2.0.0 edge SDK, v1/v2 dependency bleed, production npx/loader/network resolution, MCP session, GET stream, initialize-only modern proof, or failed dual-era codec test blocks activation. The first-cutover seal and all of its derived receipts/digests are invalid for recovery activation.
- Any selector or launcher path that accepts either frozen revoked digest, reaches a revoked distribution root's manifest/file bytes, writes a pointer/receipt for it, consumes a rollback receipt for it, permits a registry override/alias/fallback, or changes non-revoked behavior blocks reseal and activation.
- Any SSRF build that retains `[0x64000000, 0x657fffff]`, blocks public `100.23.203.190` through that row, permits actual RFC 6598, lacks exact source/anchor/event/postimage proof, or weakens another SSRF class blocks reseal. Any synthetic per-server preflight proof that constructs/dispatches the rejected transport, fails to continue through all three Things backend definitions, or leaks an unsanitized error blocks reseal. Actual provider/catalog proof belongs only to the fresh post-seal S2-01A/L00A no-bind gate.
- Any recovery that removes/disables DeepWiki or another unrelated server, contracts full runtime settings to the isolated no-bind fixture, claims MCPHub 1.0.32 has native group-scoped startup, moves a Things server outside the sole `things` group, or uses a production-loader transformation blocks cutover.
- Reseal, isolated rematerialization, a fresh no-bind preselection receipt, and the separate full-topology local live gates are all mandatory. Evidence from one layer never substitutes for another.
- F0 found both fixed user-controlled Shortcuts absent and TCC readiness unproven. This does not block local bearer activation of the exact 70-tool schema/catalog: affected calls must return typed unavailable/degraded results and no raw/UI/database fallback or operational claim is permitted. It does block remote/public activation until fresh bridge/TCC and observed-wire gates pass.
- The F0 runtime/process capture is temporally inconsistent/stale. Fresh provenance immediately before cutover is mandatory.
- Any OAuth, CIMD/DCR, protocol, ingress, offline-conformance, or observed-wire failure keeps the public route disabled. Local/offline success never substitutes for current observed ChatGPT compatibility.
- Dirty-tree failures are classified by exact-path diff and clean/isolated evidence where available; unrelated failures are reported, not overwritten or misrepresented.

## Authorized, Gated, Or Deferred Checks

- Shortcut import/construction is a user-controlled manual action after source proof.
- S4, F5, J5, remote implementation, and restricted remote apply are explicitly authorized for the current continuation. A missing bridge/TCC prerequisite, observed-wire handshake, or authenticated ChatGPT UI is a blocked proof layer; it is never relabeled `not authorized` and never bypasses a receipt or fail-closed gate.
- ChatGPT app/Project creation and readback require authenticated UI access and are complete only with UI readback; unavailable UI is reported as blocked without promoting source/offline proof.
- Live mutation is off until both the environment flag and separate explicit user approval exist.
- Atomic conventional commits and a non-force push are explicitly authorized after exact-path staging and final validation. Deployment publication beyond the scoped MCPHub tunnel and global skill installation remain outside this change unless separately authorized.
